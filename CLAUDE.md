# Repository Guidance

This repo stores shared skill and agent source files for Claude Code and Codex.

- Edit `skills/*/SKILL.md` and `agents/*/AGENT.md` as the canonical source. Never create skills or
  agents directly under `~/.claude/skills`, `~/.claude/agents`, or `~/.codex/skills`.
- The `name:` in frontmatter must match the directory name, or `build.sh` fails. Agent names must
  end in `-agent`.
- Ask before deciding whether a new skill or agent belongs in the public root or in `private/`.
- Do not edit `dist/` directly. It is generated by `build.sh` and gitignored.
- Re-run `./install.sh` (no args) after adding or removing files. With no `--host`, it installs every detected host (Claude + Codex) and runs `build.sh` for Codex. Do not use `--host claude` alone; it silently skips Codex.

## Repo layout (two repos)

- This repo (`rcedwards/blaude-bode`) holds shareable skills/agents under `skills/` and `agents/`.
- `private/` is a SEPARATE nested git repo (`rcedwards/blaude-bode-private`) with its own remote, gitignored here. Personal and onX-internal skills/agents live there under `private/skills/` and `private/agents/`. Commit private changes inside `private/`, not from this repo.
- `dist/` and `private/` are both gitignored here, so building private skills into `dist/` does not leak them into this public repo.

## Auto-install hooks

- `./bin/install-git-hooks` sets `core.hooksPath=.githooks` for BOTH this repo and the nested `private/` repo (run it once per clone).
- This repo: `pre-commit`/`post-merge`/`post-checkout` rebuild `dist/` when Codex source changes; `post-commit` runs `./install.sh` (all hosts) when a skill/agent entrypoint changed.
- `private/` repo: `post-commit`/`post-merge`/`post-checkout` run this repo's `./install.sh` (all hosts) so private skill changes auto-install too.
- Hooks tolerate `claude`/`codex` not being on PATH (e.g. GUI git contexts) and never block a commit.

## Claude-specific notes

- Skills are installed as symlinked source directories under `~/.claude/skills/`.
- Agents are installed as symlinked markdown files under `~/.claude/agents/`.
- Frontmatter fields such as `allowed-tools`, `requires`, `hooks`, `model`, and `tools` are preserved for Claude.

## Cross-host notes

- Keep markdown bodies shared unless the distinction is unavoidable.
- Codex strips Claude-only frontmatter, so required operational steps should also be described in the body when they matter for correctness.
- Prefer extending `build.sh` and `install.sh` instead of creating duplicate Claude-only and Codex-only source files.

## Security and privacy

This is a public repository. Never add secrets, credentials, tokens, personal data, customer data,
internal URLs, private repository names, private infrastructure details, or company-specific names
and identifiers to source files, examples, tests, fixtures, logs, commit messages, or documentation.

- Use unmistakably generic placeholders such as `owner/repo`, `example.com`, `<token>`, and
  `<internal-service>`. A prohibited-content example must not contain a real or realistic private
  identifier.
- Do not copy content from `private/` into this repository without reviewing and sanitizing every
  line. If material is personal, organization-specific, or uncertain, keep it in the nested private
  repository.
- Before every commit, inspect the full staged diff with `git diff --cached` specifically for
  sensitive information. Stage only intended files; do not rely on `.gitignore` as a privacy check.
- If sensitive information may already have been committed or pushed, stop. Do not merely delete it
  in a later commit; notify the user so credentials can be rotated and repository history can be
  cleaned deliberately.
